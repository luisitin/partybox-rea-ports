# Assumptions

- This job is the owner's public REA queue task. Its explicit clone, claim, branch, verification and PR instructions govern this work instead of unrelated PartyBox board-task procedures.
- Research applies to the classic automatic-bounce platform loop. Themes and native versions vary; the port does not claim byte-for-byte fidelity or the original's unpublished physics.
- Original exact bounce impulse, gravity, horizontal speed, camera threshold and height-to-score conversion were not verified. Numeric values in the inspected JavaScript recreation are that author's constants. PartyBox values are original tuning.
- The native app was not installed or played during this research task. Original mechanics were cross-checked using the developer's listing and independent firsthand reviews. Public recreation source was read and its README-linked game was played in one isolated headless Edge browser at 390 × 844: automatic start, ArrowLeft held 250 ms/released, then ArrowRight held 250 ms/released. `research-play.json` records the actions and 390 × 844 canvas. Its temporary screenshot was not committed. No recreation art, sound or code was copied into the port.
- Browser action metadata does not establish measured character displacement, native gravity or native bounce timing. The 250 ms key holds describe requested input durations; no timed native audiovisual measurements are claimed.
- Hold-left/right satisfies P15's "tilt or hold" requirement on devices with no motion permission. The two controls are the reliable default; motion input is unnecessary for a complete game.
- Three rounds of at most 60 seconds, identical seeded courses, isolated climber cameras, maximum-height scoring and fair ties are deliberate PartyBox adaptations. They are not native game's durations or multiplayer rules.
- Movement/collision sampling remains 20 ms. Server timer/broadcast cadence is 200 ms; these intervals have different purposes, and the reachability analysis uses the 20 ms physics samples.
- Platform randomness must always leave a reachable stable path under the port's own physics. Optional risky platforms may change the route; they must not make luck determine whether progress is possible.
- The original includes enemies/shooting and more power-ups. P15 specifies an automatic-bounce climbing race; added complexity is chosen for living-room clarity rather than an exhaustive inventory of native themes.
- Research websites' runtime advertising and telemetry are never part of this port. The game makes no runtime network calls and uses only original art plus existing SDK audio.
