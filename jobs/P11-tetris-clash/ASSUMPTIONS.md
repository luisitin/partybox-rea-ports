# P11 assumptions

1. The owner's current request authorizes the REA queue in `C:/dev/rea-runs/r11`, its `CLAIMS.md` main commits and public PRs. Those explicit instructions take precedence over the team manual's normal PartyBox-core worktree/board workflow. The owner's PartyBox checkout and team board are outside this task.
2. P11's public display name is **Block Clash**. The source product name remains only in research citations and the queue's existing job ID/folder. Rules are reimplemented; no original branding or assets ship.
3. The contract's shell has already explained the manifest rules and completed ready-up/countdown before `init`. This game starts directly in live play.
4. Every initial seat sees the same seeded seven-bag sequence, at its own cursor. The seed and complete future sequence stay server-side. Current/preview data is exposed only where the game design needs it.
5. P11's 120-second limit takes precedence over longer original timed modes. At the limit, surviving seats rank ahead of eliminated seats; deterministic tiebreaks and shared ties are documented in the game spec.
6. Garbage details vary across products. Block Clash uses an explicit, documented attack table and cancellation order. It does not claim full official guideline certification; port choices such as mini-spin support, attack caps and lock timing must match the implementation/spec.
7. Touch gestures have labeled button alternatives. Rival selection and pending garbage are visible while playing. Phone-only users get the board and standings locally; spectators never receive actionable controls.
8. Disconnected seats continue under server gravity and never hold the match open. Refresh resumes existing state. Permanent departures are handled by the reducer and preserve the seat in final results.
9. Research used public code, original manuals and papers with independent cross-checks. The runner opened the official live game in isolated headless Chrome and clicked Play. Its title, Hold/Next panels and menu rendered, but Play led to a persistent black canvas. Live movement and original audio could not be measured. This gap is retained honestly; source reading supplies mechanics evidence under RULES.md's web fallback.
10. Direct opening of the manufacturer's Challenge PDF (`I1045.pdf`) timed out. Indexed text was available; the accessible licensed battle manual (`I4063.pdf`), Xbox help and public Kotlin implementation provided the needed versus evidence. A GitHub tree page also failed, so the public GitHub API/raw-source route was used.
11. Original art is authored as SVG/CSS using PartyBox tokens. Audio is optional and must be original if present; the licensed theme and source artwork are excluded.
12. PowerShell blocks the pnpm.ps1 shim; commands use pnpm.cmd. The connected CUA browser inventory was empty. The existing Chrome executable is used for scoped headless inspection/captures, with one isolated process and cleanup in finally. No new dependencies are installed.
13. The clone omits docs/ADDING_A_GAME.md, registry generators and the core team's pb submit workflow. The owner explicitly requires this public workshop's typecheck, format, game-scoped tests and PR workflow; those available checks are used here.
