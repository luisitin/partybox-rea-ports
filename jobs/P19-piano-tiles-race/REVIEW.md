## Server requirements assessed

- The course comes exclusively from the SDK PRNG. Initial generation and tail extension return a new RNG/state; no clock, random source or I/O is read by the server.
- All players share one sequence. Extension occurs before a correct tap would reduce the next-four-note window, so ordinary advancement does not reach an undefined target. The same generated tail is reused by every player.
- A correct current row increments exactly one tile; a wrong current row changes only its owner to out. Future/stale rows and out/disconnected/unknown senders cannot change a run. Same-row packet retries are server-idempotent.
- The authoritative shared deadline rejects inputs on or after its end. Matching timers wake every 100 ms; stale and premature timers are ignored. One survivor keeps racing; all-out ends promptly; an absent living player cannot extend play beyond 30 seconds.
- Score is derived from tile counts with SDK shared ranks and complete results. There is no accidental speed, survival or failure-time tie breaker and no repeated score accumulation.
- Disconnect changes connection status without removing counts. A reconnect resumes the same row. Unknown prototype-like sender names are gated with hasPlayer rather than object truthiness.
- TV/spectator views contain public standings, not RNG or a course. Each alive player sees only its current four notes. Changing another unseen part of the course should leave that controller's view unchanged.
- Three bot strengths differ in delay and error probability. They target their visible note, stop while paused/out/disconnected and refuse to act past the shared deadline. The cadence is a constant per strength; seeded jitter could be a later feel improvement if bot traces appear synchronized.
- The SDK's intended totality domain is schema-valid inputs; fuzz.ts explicitly excludes schema-invalid input. The phase reducer safely handles injected malformed numeric positions, but does not itself parse arbitrary null input objects. No issue is claimed from that outside-contract case.
