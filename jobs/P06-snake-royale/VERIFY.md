## Defects fixed in the quality loop

- Authoritative snapshots now arrive every 100ms rather than 600ms. Bots decide at most once per simulated second, independently of human input and snapshots.
- Body sampling uses 1.6-unit spatial spacing; equal-mass sprinting no longer stretches the lethal body.
- Head contact still kills both when one head also hits a wall, independently of seat order.
- Eight simultaneous maximum-mass corpses retain 90 mass each within the 240-piece cap.
- Returns choose among 31 deterministic ring/interior body-clear candidates; the clearest candidate is the fallback when every candidate is crowded.
- Movement before a disconnect/rejoin is settled with the old presence, paused movement stays frozen, and absent seats start new rounds offstage.
- Compass input uses the rendered SVG coordinate system. Tracked key releases work after text focus/modifier changes; both thumb targets work together.
- Snake numbering survives arbitrary player IDs and SDK roster sorting. Disconnected phones disable controls with a reconnect notice; paused spectators have a status line.

## Runner failures retained as evidence

The initial current-game baseline passed 110 checks but hit the workshop's 20s wall timeout in the SDK skipper case (81s under load). The wrapper now grants 120s without changing SDK assertions; all 20 passed. A formatter initially walked the runner's nested claims worktree; that owned worktree was moved outside the repo, and regenerated media was formatted. Browser local-file navigation timed out, so offline HTML is injected into the page directly; the browser still closes in finally. A harness incorrectly omitted the released touch contact; explicit touchEnd for that contact made native two-thumb release pass without a production-code change.

Historical food-loop differential/microbenchmark reports concern an equivalent collection-only change. They do not measure the later gameplay changes or promise whole-game speedups. Reproducible scripts remain under experiments/food-loop/.
